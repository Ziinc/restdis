name: docs
description: "Write or revise documentation in plain, precise language. Use this when drafting or editing docs, guides, or explanatory text."
---

Write the documentation in plain language that a non-expert reader can follow. Follow every rule below.

- Rephrase dense or technical content so a reader who is new to the topic can understand it. Do not just state a fact, explain it enough for that reader to follow.
- Keep technical terms only where they add value or clarity for the topic (for example, software terms). Do not remove a useful term just because it is jargon, and do not add a term that is not needed.
- Follow Orwell's rules for writing: prefer plain words over fancy ones, cut every word that adds nothing, use the active voice, use everyday English over foreign or scientific words, and never use a metaphor you have seen before.
- Follow ASD-STE100 (Simplified Technical English): one thought per sentence, short sentences, and no jargon except standard software terminology (for example: API, database, endpoint, function, variable, deploy, commit, branch, cache, query, schema).
- Do not write a checklist. No "- [ ]" or "- [x]" items.
- Do not use em dashes. Use a comma, a period, or a new sentence instead.
