---
name: pr-writing
description: "Write pull request descriptions in plain, precise language. Use this when drafting or revising a PR title and description."
---

Write the PR description as a bullet list. Follow every rule below.

- Use at most 3 bullet points.
- Write each bullet as one short sentence that states one change.
- Follow Orwell's rules for writing: prefer plain words over fancy ones, cut every word that adds nothing, use the active voice, use everyday English over foreign or scientific words, and never use a metaphor you have seen before.
- Follow ASD-STE100 (Simplified Technical English): one thought per sentence, short sentences, no more than one instruction or fact per bullet, and no jargon except standard software terminology (for example: API, database, endpoint, function, variable, deploy, commit, branch, cache, query, schema).
- Do not write a checklist. No "- [ ]" or "- [x]" items.
- Do not use em dashes. Use a comma, a period, or a new sentence instead.
- Do not use headers (no `#`, `##`, or bold section titles). Write the bullets directly.
